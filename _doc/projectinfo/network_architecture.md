# 局域网、播放与恢复架构

## 两个服务边界

本机管理服务由平台端口启动，Host/Origin 校验加上每次启动生成的 CSRF 凭证保护写接口。局域网服务在界面确认后才绑定用户所选私有 IPv4，第一次由系统分配空闲端口，记录端口用于下次开启。端口被占用时明确失败，可重启应用后在设置中重置端口（后续如需自动选择新端口需同时提示旧地址失效）。

局域网仅提供显示 HTML、必要本地 JS/CSS/语言文件、配对申请、会话授权、已授权素材和 WebSocket。主控页面及管理 API 不对局域网开放。

## 配对协议

6 位随机码 10 分钟有效；同一 IP 每分钟最多 12 次申请；最多 50 条待确认申请，2 分钟过期。主控批准后设备用申请 ticket 一次性取得随机设备令牌。SQLite 只存 SHA-256 摘要。用户可随时撤销，立即断开连接。

设备令牌存于显示端同源 localStorage；POST /session 验证后设置 HttpOnly / SameSite=Strict Cookie 用于原生视频 Range 请求，不把令牌放进 URL。WebSocket 首条消息认证，5 秒超时；最多 64 个连接，单消息上限 8KB。断线自动退避重连。

## 场景与同步

逻辑屏幕属于活动，设备绑定逻辑屏幕。场景保存各屏幕背景及按顺序叠放的图层；图层采用百分比位置尺寸，文字字号按画面高度百分比计算，支持图片、视频、文字叠加。保存时验证素材与屏幕属于同一活动。

执行生成独立 cue、递增版本、执行快照与服务端未来 3 秒的起播时间。显示端最小往返时间采样估计时钟偏移，保留旧画面准备新内容，按统一时间计算循环视频位置。250ms 检查，较大偏差 seek，小偏差通过 0.95–1.05 倍速校正。主控可见设备上报的实际校正前偏差、版本与准备状态。网络波动、解码速度与浏览器调度会影响精度。

暂停记录相对播放位置，继续调整时间轴，所有设备根据当前完整状态恢复。黑屏同时停止声音，恢复后按时间轴追赶。每屏视频可独立静音、音量、循环；首次进入显示端需人工点击以便允许有声播放，浏览器仍可能要求再次点击。

## 恢复与安全

场景执行快照在内存，最后场景 ID 在 SQLite。主控重启不自动展示，不自动开局域网。断网时设备保留已获取的内容，视频是否持续可播取决于缓冲；重连后以服务端完整状态为准。素材或解码失败在显示端及主控呈现。

工作数据备份和恢复仅在本机管理端提供，要求停止展示并关闭局域网；不将备份目录或整个数据目录静态公开。详见 work_backups_architecture.md。

## 按屏幕执行（2026-11-10 修订）

同活动执行场景时，仅更新该场景 layout 中显式存在的屏幕，未配置的屏幕保留原画面及视频时间轴。screenStates 为每屏保存 scene/cue/startAt/position/paused/version，deviceState 使用绑定屏幕的状态。多屏同场景获得相同起播时间；不同场景独立执行时版本可以不同。显式空图层清空对应屏幕，完全无屏幕配置的场景禁止执行。跨活动切换则清空旧活动输出。

全局暂停/继续针对各屏分别计算相对位置。人工恢复使用上次多屏配置快照，统一从头启动，启动时仍默认待命与关闭局域网。主控显示各逻辑屏幕当前场景。

## 图层动画

layout.layers[].effect 保存 type（none/left/right/up/down/fade/pulse）和 duration（每轮1–120秒）。服务端白名单校验，旧场景自动补无特效。public/effects.js 同时供 Node 参数验证、React 预览和显示端使用；滚动按可见区域与内容实际宽高计算，兼容长文字。显示端 requestAnimationFrame 按统一起播时间/暂停位置计算动画相位；不涉及屏幕的独立场景执行不会重置动画。

## 删除与播放隔离

/api/deletion/preview 返回引用场景、受影响的正在播出屏幕、设备解绑影响及确认指纹。确认删除时重新检查指纹，引用、配置或播放状态变化会要求重新确认。只停止受影响的 screenStates，保留其他输出时间轴；数据库事务修改引用并删除记录，再广播当前状态。恢复快照移除对应输出，防止重启恢复已删除内容。文件清理仅处理被删除的素材文件。
